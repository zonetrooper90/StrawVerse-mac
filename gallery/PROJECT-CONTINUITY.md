# Gallery development continuity

Approved 2026-11-04; revised 2026-11-12. Historical archive: `gallery/development-archive`. Active checkpoint/work branch: `gallery/development-clean`. Prior recovery branch: `gallery/working-2026-11-10-coordinated-fades` (read-only).

1. Every explicitly **approved** design or behavior decision must be recorded in `gallery/APPROVED-DECISIONS.md` on GitHub, clearly separated from proposed ideas and open questions.
2. Every approved new numbered Gallery HTML build must be committed as a **complete, exact, immutable, SHA-256-verified** snapshot (direct HTML or a byte-exact reconstructible archive). New checkpoints live under `gallery/checkpoints/` with an updated `gallery/checkpoints/current.json`; never overwrite an earlier version. Archive experiments separately.
3. Discuss changes before implementing them and get the user's explicit approval before creating a new numbered version. Do not use a standalone experiment as the new app build.
4. Verify every GitHub upload. If upload fails, disclose the failure, inspect the actual remote state before retrying and do not claim the version is backed up. Never promote an unverified local build to the baseline.
5. At the start of future Gallery conversations, read `AGENTS.md`, `gallery/WORKFLOW.md`, this file, `gallery/DEVELOPMENT-STATE.md`, `gallery/APPROVED-DECISIONS.md`, and **restore/checksum-verify the checkpoint named by `gallery/checkpoints/current.json`**. Never guess which downloaded HTML was the latest. GitHub is the source of truth.
6. No image generation or image editing without the user's **explicit prior approval**. For UI changes, use actual HTML/CSS rather than generating visual stand-ins.
7. Protect stable versions and experiments. Do not overwrite `main`, native Mac build branches, or earlier HTML versions. Keep Apple Silicon-only Mac build compatibility and StrawVerse source/repository compatibility.
8. This is a per-session working rule, **not a background automation**. GitHub commits must be performed and verified during a conversation while the connection is available.
9. **Mandatory user download:** after GitHub checkpoint verification and both CI passes, provide a commit-pinned GitHub file-page link to the exact verified `gallery/Gallery-current.html` and a separate build commit link. The user clicks GitHub's Download raw file control. ChatGPT attachments are optional, never mandatory; avoid transferring the large HTML solely for an attachment. See `gallery/WORKFLOW.md`.
10. **Persistent handoff:** record approved pending work, verified completed milestones, actual user-testing status and next proposed step in `gallery/DEVELOPMENT-STATE.md`. In any new conversation or after an error, reconcile this record against the remote head, pointer, manifest and CI before resuming. No duplicate publishing requests; do not infer that a tool error means the remote operation failed.

Old HTML history: `Gallery-v96.html`, `Gallery-v97.html`, `Gallery-v98.html`, `Gallery-v99.html`, plus standalone experiments. The latest immutable, reconstructible checkpoint is always the one named by `gallery/checkpoints/current.json`; see `gallery/DEVELOPMENT-STATE.md` for the handoff and testing status. Historical synchronized-fade, sequential-fade and A+C snapshots remain available.  Follow `gallery/WORKFLOW.md` on every future build.
